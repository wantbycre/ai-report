# Project Refactor Audit Guide

## 프로젝트 구조

```
src/
├── pages/                  # 페이지 단위 모듈 (리팩터링 완료 대상)
│   └── [page]/
│       ├── index.tsx       # 또는 [Page].tsx
│       ├── components/
│       ├── hooks/
│       ├── queries.ts
│       ├── fetchers.ts
│       └── types.ts
├── components/             # 공통 UI 컴포넌트
├── lib/
│   ├── api/
│   ├── styles/
│   ├── const.ts
│   ├── types/
│   └── utils/
└── store/
```

## 감사(Audit) 목적

리팩터링 완료 후 아래 항목을 전수 검증한다.

---

## 체크리스트

### 1. Import 경로 검증

- src/ 전체에서 `from '.*features` 패턴을 grep하여 잔여 참조 탐지
- 존재하지 않는 경로를 참조하는 import 탐지
- 상대경로 오류 (../../ 등 depth 불일치) 탐지

### 2. 페이지 누락 확인

- 리팩터링 전 src/features/ 에 존재했던 페이지 목록과
  현재 src/pages/ 목록을 대조하여 누락된 페이지 탐지

### 3. 삭제된 features를 아직 참조하는 곳 탐지

- src/features/ 가 삭제 또는 이동되었음에도
  다른 파일에서 해당 경로를 import하는 케이스 전수 탐지
- 대상 범위: src/ 전체 (.ts, .tsx, .js, .jsx)

### 4. 페이지 구조 완결성 확인

- src/pages/ 각 폴더가 아래 구조를 갖추었는지 확인
  - [ ] index.tsx 또는 [Page].tsx 존재
  - [ ] components/ 폴더 존재
  - [ ] hooks/ 폴더 존재
  - [ ] queries.ts 존재
  - [ ] fetchers.ts 존재
  - [ ] types.ts 존재
- 누락 항목은 목록으로 보고한다 (**자동 생성 금지**)
- 레거시 프로젝트로 순차 변경 목적 (자동 생성 금지)

### 5. 빌드 검증

- `npm run build` 또는 `tsc --noEmit` 실행
- 에러 발생 시 에러 메시지와 파일 경로를 정리하여 보고
- 경고(warning)도 함께 수집

---

## 작업 규칙

1. 내부 로직은 절대 변경하지 않는다
2. import 경로 수정만 허용한다
3. 파일 신규 생성 금지 (누락 구조 자동 보완 금지)
4. 불확실한 경우 수정하지 말고 보고만 한다
5. 작업 전 반드시 현재 상태를 분석하고 변경 계획을 먼저 제시한다
